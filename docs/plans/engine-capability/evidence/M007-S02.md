**The check found a guard on its first run, which is what it exists for.**
`scripts/check-release-workflow.mjs` locks the release workflow's shape in 27
tests — that no Linux plugin zip returns, that the validator flag stays on, the
build → validate → pluginval → sign → package order, the zip layout — and **no
workflow runs it.** `release.yml` names it in three comments and never invokes
it. It was worse off than the eleven `GAP03` counted: those at least ran in CI.

It is runnable and passes (27 tests, 0 failures), so it was added to
`check-guards.sh`, which is now 13 invocations. S01's measurement missed it
because that list was derived from `ci.yml`, and this guard belongs to
`release.yml` — a reminder that a survey is only as wide as the file it greps.

**A correction to the check's own sources.** The first run reported all eleven
S01 guards unreachable, because `.jk/validations.yml` names
`bash scripts/check-guards.sh` and not the guards inside it. The wrapper is
itself a declared token, so what it runs is reachable through it; it is now one
of the five sources.

`check-wasm-freshness.sh` carries the first `local-unrunnable` marker. It is
named by the `wasm-freshness` token, so the check passes on reachability alone —
the marker is there because running that token without a URL exits 2 rather than
checking anything, which a developer deserves to be told. The marker path itself
is proved by task 2's probe.
