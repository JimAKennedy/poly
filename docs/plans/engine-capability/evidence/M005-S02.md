Test first: the schema case was changed to expect version 4 and to assert the
`onsets` contract, and failed with `schemaVersion=3, expected 4 (M005/S02
timeline onsets)` before any emitter change.

The three patterns M001/S02 authored are now readable from the file that could
not previously express them:

| Preset | Lane | `onsets` |
|---|---|---|
| `Cuban Son Montuno` | clave | `[0, 3, 6, 10, 12]` |
| `Rumba Clave` | clave | `[0, 3, 7, 10, 12]` |
| `Clapping Music` | clap | `[0, 1, 2, 4, 5, 7, 9, 10]` |

46 lanes run in timeline mode and 46 carry `onsets` — an exact match, which is
what shows the emit condition is the timeline flag and nothing else. The test
asserts both directions: a timeline lane must carry the array, and a lane that
is not in timeline mode must not, because the field's absence is what says the
pattern is derived rather than authored.

The version bump moved all three functional sites together — the emitter, the
generator's guard, and the schema test — so the generator never had to read its
own output at a version it rejects. Three comment-only references to version 3
were corrected. `webui/tests/startup.spec.mjs` was left alone: its
`schemaVersion` is the WebUI bridge's `POLY_SCHEMA_VERSION`, a different number
that a grep for the word finds and that looks like it belongs.

Regenerating twice produced a byte-identical file, so the new field introduces
no ordering or formatting non-determinism. The first check written for this was
wrong — it compared against `HEAD`, where the file is legitimately modified —
and was replaced with a before/after comparison of two consecutive runs.

## M005/S02 — task 2: answer the son-clave question from the JSON, and close the slice

- `format` → exit 0
- `unit` → exit 0, 592 tests, 0 failures

- `doc-conformance` → exit 0, 256 tests, 0 failures (up from 255 — the new case)
- `ledger` → exit 0, conforms with the slice `done`

**The case went into `preset-table-conformance.test.mjs`, not the schema test
and not a new sibling.** The plan left the location open; the deciding fact is
that `presets-json-schema.test.mjs` is not listed in
`scripts/check-doc-conformance.sh`. It is one of the seven files
[#272](https://github.com/JimAKennedy/poly/issues/272) names as unprotected, so
it runs only under `site-unit`, which CI does not run. A new sibling would have
been equally invisible. `preset-table-conformance.test.mjs` already imports
`presets.json`, is on the doc-conformance list, and the count rose from 255 to
256 — which is the evidence the case actually runs in CI rather than only here.

**A limitation this slice does not fix, and should not be read as fixing.**
M005/S01's count guard lives in `presets-json-schema.test.mjs`, which is in that
same unprotected set. It bites locally and in the pre-push gate; it does not
bite in CI. PIPE01's definition of done said "fails the site suite", which is
met, but a reader should not infer CI protection from it. That gap is #272's.

Both arms of the case were proved, and they need different mutations because the
second is unreachable while the first holds:

- clave onsets set to `[0,3,6,11,12]` — wrong but not Euclidean — failed with
  `Cuban Son Montuno clave onsets are [0,3,6,11,12], but theory-afro-cuban.mdx
  states [0,3,6,10,12]`
- onsets **and** the expected literal both moved to `[0,3,6,9,12]` failed with
  `Cuban Son Montuno clave carries E(5,16) rather than the authored pattern
  theory-afro-cuban.mdx states`. This is the arm that matters: it catches
  someone updating the expectation to match wrong data, which the first arm
  cannot see.

**The first attempt at both mutations silently did nothing** and was caught
before being recorded. It edited `"onsets":[0,3,6,10,12]` as a single-line
string; the emitted JSON is pretty-printed, so nothing matched, both runs stayed
green, and that would have read exactly like a passing proof. Redone with
JSON-aware edits. A mutation round that cannot fail is the same defect as a
predicate that cannot fail, and this programme has now hit both.

`presets.json` was restored by regenerating, not by hand-editing back;
`git diff --quiet` is clean.
