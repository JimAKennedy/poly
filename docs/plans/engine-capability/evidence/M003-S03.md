The Manding Djembe preset's three lanes now carry an eight-step profile built
from `{1.06, 0.94}` — a systematically long-first beat subdivision — where they
previously ran dead-on the even grid.

**The source needed no new bibliography entry.** `fr-polak-2010` is already
there at `data-tier="A"`, described as "measured microtiming showing jembe
subdivision is systematically uneven". The slice's first definition-of-done
item asks for a citation the check accepts, and the citation already existed;
what was missing was the data.

**What the comment says, and why it matters.** The catalogue entry states that
this encodes the *shape* Polak reports, not a transcription of a published table
of ratios, and that the depth is Poly's. Refining the values against a source in
hand is then a data change needing no code — which is the distinction row B10
drew when it separated the mechanism from the data. Claiming these are the
measured numbers would be the kind of citation this programme's first milestone
existed to remove.

**A wrong-anchor edit, caught by the test.** The profile first landed in
`makeEweEnsemble`: the anchor used to place it was a `// M070 S04: metronomic
tradition` comment that appears **nine** times in `presets.cpp`. The preset case
failed and `presets.json` showed no profiled lanes on Manding Djembe, which is
how it surfaced. The edit is now scoped to the function body by name.
