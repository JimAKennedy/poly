## M004/S02 — task 1: the preset sweep, its contract, and the workflow step

- `format` → exit 0
- `cubase-harness` → exit 0: typecheck clean, 23 Playwright unit cases, 35 Python cases

`lib/preset-contract.ts` reads `site/src/generated/presets.json` into one
expectation per preset and compares it against what the host showed. It throws
rather than returning a partial list when the file's shape is wrong — a contract
built from a file that silently changed is worse than none, because the sweep
would then compare against nothing and report success.

Nine unit cases prove the comparison decides both ways without a DAW: a wrong
lane count, wrong note numbers, a preset never observed, every mismatch reported
rather than the first, and the mutation knob turning a correct observation into
a failure.

`preset-recall.spec.ts` selects each of the 45 presets through the shipping
menu — `#presetMenu [role="option"][data-index]` — and reads the lane count and
note numbers back from the `.strip .stat` line the WebUI renders. It clicks the
`All` category chip first: the menu filters by category, and a filtered menu
would silently skip indices rather than fail.

Two distinct assertions, deliberately:

- **the host survives each selection**, with the index named if it does not.
  That is the `kWebPresetLaneNames` crash, and the index is the only useful
  thing to know about it.
- **each preset loads correctly**, compared against `presets.json`. A preset
  that loads wrongly passes a survival-only sweep, which is the difference
  between "did not crash" and "works".

The read-back uses the shipping DOM rather than a debug state dump, because
there is no such dump in the embedded host and adding one would put test-only
code in the product.

**Not yet proven against Cubase.** `cubase-harness` does not run a DAW. This
slice's row stays `open` until a nightly names it, per the milestone's own rule.
