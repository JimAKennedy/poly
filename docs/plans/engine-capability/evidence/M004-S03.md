## M004/S03 — task 1: the motion, the comparison, and the workflow step

- `format` → exit 0
- `cubase-harness` → exit 0: typecheck clean, 40 Playwright unit cases, 39 Python cases

**The property, stated positionally.** What Poly emits at a PPQ is a function of
that PPQ, not of how the transport arrived there. Golden tests enforce
determinism for linear playback only — and linear playback is the one case where
a derivation and an accumulator agree. They diverge the moment the transport
jumps.

**A design constraint found by reading the probe rather than assuming.**
`writeJsonl` truncates and re-writes the whole accumulated event list on every
flush, so one session yields one cumulative JSONL. That means a second capture
is neither available nor needed: a locate-back puts the same PPQ range in the
file twice, and `splitPasses` cuts the stream at the backward jump. It also
means the locate would have injected a replay into the golden comparison's
window — so `compare_probe_golden.py` gains `--first-pass-only`, scoping it to
the linear passage the golden was always about, in the same spirit as its
existing tail trim. Both sides use the same backward-jump rule, and the Python
and TypeScript implementations say so in each other's terms; if they disagreed a
note could fall into neither half.

**A weakness the unit tests caught in the predicate.** The first comparison
compared only positions present in *both* passes. The red-path case failed, and
the reason was the real finding: an accumulating lane shifts notes **off** the
positions they should occupy, so the revisited position simply goes silent and a
both-sides-only comparison sees nothing to compare. It now compares across the
passes' overlapping range with an absent side counting as a divergence, and a
case pins exactly that — `a position that goes silent in a later pass is
reported`.

The synthetic fixtures were also non-periodic-ised: with pitches `36, 38, 36` a
one-bar shift maps 36 onto 36, and the red-path case passed for the wrong
reason.

**A vacuity guard, because this programme keeps finding vacuous predicates.**
`requireRepeatedVisits` throws if the capture has a single forward pass or no
overlapping positions. Without it, a run where the locate never took effect
would find no divergences and report green while proving nothing.

| Case group | Guards |
|---|---|
| `splitPasses` | the cut is at a backward jump; equal-PPQ onsets do not split a pass |
| `findDivergences` | differing pitches, a silenced position, a short later pass not being a divergence |
| `requireRepeatedVisits` | a linear-only capture and non-overlapping passes are errors, not passes |
| `applyMutation` | the accumulator drift makes a correct capture diverge |
| `trim_to_first_pass` (Python) | the cut, a forward-only capture, equal PPQ, and the disabled case |

**Not yet proven against Cubase.** `cubase-harness` does not run a DAW, and one
thing here can only be confirmed on the runner: that sending `CC_LOCATE` while
the transport is rolling relocates *and keeps playing*, rather than stopping.
The row stays `open` until a nightly names it.

## M004/S03 — task 2: proved in a real Cubase, both ways

- `format` → exit 0
- `cubase-harness` → exit 0: typecheck clean, 40 Playwright cases, 39 Python cases
- `ledger` → exit 0, conforms with the slice `done`

**Green:** [run 35259088819](https://github.com/JimAKennedy/poly/actions/runs/35259088819)

> `ok 1 transport-motion.spec.ts:33:3 › L4: transport motion leaves PPQ-derived
> output unchanged (post-quit) › the located-back pass matches the first pass at
> every shared position (5ms)`

Three lines from that run matter together, because any one alone could be a
false green:

- `[driver:replay] located back to the left locator; replaying the passage` —
  the transport really jumped.
- `probe=94 golden=94` — the first-pass trim hands the golden exactly the
  passage it describes, where the previous attempt handed it 45.
- the assertion passed **without** `requireRepeatedVisits` throwing, which it
  would have done had the capture held a single forward pass. The green is
  therefore a green about something.

**Red:** [run 35259758615](https://github.com/JimAKennedy/poly/actions/runs/35259758615),
dispatched with `e2e_mutate=s03-accumulated-phase`

> `ppq 16.5: pass 0 emitted [42], pass 1 emitted [36,38,42,45]`

Only the transport assertion failed. The toggle, export and preset-sweep specs
all stayed green in the same run — and the preset sweep's own knob was not set —
so the list-valued `POLY_E2E_MUTATE` selects exactly the spec it names.

**What the earlier red run taught.**
[Run 35258279739](https://github.com/JimAKennedy/poly/actions/runs/35258279739)
failed the golden comparison with `probe=45 golden=94`. The locate had worked;
firing it four seconds into an eight-second passage simply cut the first pass in
half, so `--first-pass-only` handed the golden half a performance. The replay is
now tied to the completed pass rather than to a number of seconds, which also
means it cannot drift from `TAIL_SECONDS`.

**What only the runner could confirm:** that `CC_LOCATE` sent while the
transport is rolling relocates *and keeps playing* rather than stopping. It
does — `[driver:replay]` is followed by a second pass in the capture.
