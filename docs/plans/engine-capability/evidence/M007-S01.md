# M007/S01 — evidence

## M007/S01 — task 1: the wrapper and the `guards` token

- `format` → exit 0
- `doc-discipline` → exit 0
- `guards` → exit 0, 12 guard invocations passed

Twelve invocations cover the eleven guards: `check-sample-manifest.sh` runs
twice, with `--strict` and `--coverage`, because CI invokes it twice and running
it once would check less than CI does.

**The script deliberately does not use `set -e`.** A developer wants every
broken guard from one run, not one per invocation, so a failure is recorded and
the run continues. Task 2 proves that by breaking two at once — a behaviour `-e`
would have removed silently.

Both slices' validation lines now name `guards`. S02 creates and deletes a probe
script, and `check-scripts-readme.sh` — one of the eleven — fails on a script
missing from the README, so the token is what catches a probe left behind.

Adding `check-guards.sh` to `scripts/README.md` was not bookkeeping: that README
is guarded by `check-scripts-readme.sh`, which this very script runs, so
forgetting it would have failed the command being added.

**One tree break surfaced both kinds of guard.** A tracked file carrying a
personal-machine path failed `personal-paths` *and* `personal-paths contract` —
the shell guard and its green/red proof — so the definition-of-done item asking

**The no-`set -e` decision was proved, not asserted.** Adding a second break —
a failing assertion in `check-scripts-readme.mjs` — took the run to three
failures, and all three were named in the summary. With `set -e` the run would
have stopped at the first and the developer would have fixed one guard at a
time, which is the behaviour the script exists to avoid.
