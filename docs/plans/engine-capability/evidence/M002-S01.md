# M002/S01 — evidence

## M002/S01 — task 1: `KotekanMode`, the overlap field, and the derivation

- `format` → exit 0
- `unit` → exit 0, 599 tests, 0 failures
- `engine-isolation` → exit 0, 476 tests, 0 failures
- `rt-safety` → exit 0
- `webui-e2e` → exit 0

Seven tests went in first and failed to compile on `no member named
'KotekanMode' in namespace 'poly'`, which is the right failure for fields that
do not exist yet.

**The source pattern is E(2,12) = {0, 6}, chosen rather than picked.** A short
search over cycles 8, 12 and 16 found it is the smallest source on which all
three modes produce *different* complements. For most sources two of the three
coincide — with E(3,8), `Telu` and `NyogCag` are identical; with E(2,8),
`Empat` and `NyogCag` are — and a test that cannot tell two modes apart proves
nothing about either. The asserted onsets are:

| Mode | Derived onsets |
|---|---|
| `NyogCag` | 1, 2, 3, 4, 5, 7, 8, 9, 10, 11 |
| `Telu` | 1, 2, 4, 5, 7, 8, 10, 11 |
| `Empat` | 1, 2, 3, 5, 6, 7, 9, 10, 11 |

**The tripwire held.** The plan said that if any determinism golden moved before
task 5, that is a defect rather than a fixture to regenerate. None moved:
`git status` shows no fixture touched, and all 599 unit tests pass with the
defaults reproducing the pre-M002 strict complement exactly.

**One test did fail, and it was right to.**
`GrooveStateCopyBenchmark.ReportsFactSizes` pins `sizeof(GrooveState)` so that
struct growth is deliberate and documented — its comments record each previous
growth against the milestone that caused it. `LaneConfig` grew 1616 → 1624
bytes, so `GrooveState` grew 13712 → 13776: eight bytes per lane across eight
lanes, from a `uint8_t` mode and an `int` overlap under four-byte alignment. The
pin was updated with a comment in the established style.

**A finding, not fixed here:** that test's failure message says "update
DECISIONS.md perf entry", and no `DECISIONS.md` exists anywhere in the tree. The
message points at a file that is not there. Out of scope for this task; recorded
so it is not lost.

## M002/S01 — task 2: serialize both fields at state version 19

- `format` → exit 0
- `unit` → exit 0, 601 tests, 0 failures
- `engine-isolation` → exit 0, 478 tests, 0 failures
- `rt-safety` → exit 0
- `webui-e2e` → exit 0, 378 passed

Two tests first, both failing on `use of undeclared identifier
'kKotekanModeStateVersion'`. The guard constant, the writer and the reader
follow `kFillEveryNBarsStateVersion` (v17) and `kLaneSeedLockStateVersion` (v18)
exactly; `kCurrentStateVersion` goes to 19.

The round-trip test gives every lane a *different* mode and overlap across both
scenes, so one field written eight times would fail it — the same reason the
seed-lock test alternates its values.

The migration test authors a state with `Empat` and overlap 3, serializes it at
version 18, and asserts it loads back as `NyogCag` with overlap 0. That is not
the authored value, and is correct: a v18 state carries no kotekan-mode bytes,
so it must load as what it actually played before this slice. Lossless by
construction rather than by conversion.

**A failure I did not wave away.** The first full run had
`HostTests.HandshakeStress_NoTearNoLoss` fail. It is a documented flake
([#274](https://github.com/JimAKennedy/poly/issues/274)) — but this slice grew
`GrooveState` by 64 bytes and that test exercises tear-free handshakes of
exactly that struct, so "known flake" was a hypothesis, not an answer. Five
consecutive isolated runs passed, and a second full-suite run passed 601/601.
Recorded here because the cheap reading would have been to cite #274 and move
on.

No determinism golden moved.

## M002/S01 — task 3: emit both fields at schemaVersion 5

- `format` → exit 0

- `rt-safety` → exit 0
- `site-unit` → exit 0, 278 tests, 0 failures
- `webui-e2e` → exit 0, 378 passed
- `doc-conformance` → exit 0, 262 tests, 0 failures

Schema assertions first, failing on `schemaVersion=4, expected 5`. The mode is
emitted by name — `"nyogcag"`, `"telu"`, `"empat"` — rather than as its integer,
so the file reads without a lookup table, the same reasoning M005/S02 used for
`onsets`. A lane deriving no complement emits neither field, and the test
asserts that direction too: the absence says the lane is independent.

All four kotekan lanes read `nyogcag` with overlap 0, which is the defaults
reproducing pre-M002 behaviour. `Balinese Kotekan` changes in task 5.

**M006 paid for itself here.** `engine/tools/emit_presets.cpp` is a mapped
source in the drift map, and this task changed it. Before M006 the doc-drift
check ran only in CI, so a missing `docs/preset-taxonomy.md` update would have
shipped and failed the pull request — which is exactly what happened to M005.
The taxonomy's **JSON schema version** table gained its row for version 5 as
part of this task rather than after a red board.

One compile error worth noting for its triviality: the emitter is outside
`namespace poly`, so `KotekanMode::Telu` had to be written `poly::KotekanMode`.
Caught by the build, fixed in place.
