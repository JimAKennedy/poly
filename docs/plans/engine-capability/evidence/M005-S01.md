## M005/S01 — task 1: make the generator always build its emitter

- `format` → exit 0
- `site-unit` → exit 0, 276 tests, 0 failures

The defect was reproduced before it was fixed, so the change is measured against
an observed failure rather than an assumed one. With `makeFourOnTheFloor`'s kick
velocity changed from 110 to 97 and no explicit build, the generator reported
`wrote 45 presets` and the JSON still said 110 — the engine and the file
disagreed, and nothing said so. After removing the early return the same run
logged `building poly_presets_emit` and the JSON said 97.

The probe was reverted and the file regenerated; `git diff --quiet` is clean on
both `engine/src/presets.cpp` and `site/src/generated/presets.json`.

The clean-tree path was proved rather than assumed, since removing a guard that
returns early is exactly the change that could break it: with `build-presets/`
moved aside, the generator logged `configuring cmake build-presets/ (first run,
engine-only)`, then `building poly_presets_emit`, then wrote 45 presets, exit 0.
The original tree was restored afterwards.

The fix is a deletion, not a staleness check. cmake is already incremental, so
an unchanged tree costs a no-op — cheaper and more honest than any mtime
comparison this script could implement correctly against C++ sources.
