`npm --prefix site test` is now a step in the `site-lint` job, placed last so
the more specific doc failures report first. That job already runs `npm ci` in
`site/` and already executes a suite through `check-doc-conformance.sh`, so no
new runner and no `ci-complete` wiring.

**Coverage was proved, not counted.** `node --test`'s default reporter does not
name the files it runs, so comparing output lines against `ls` proves nothing —
the first attempt tried that and got zero matches, which would have read as a
failure of the change rather than of the measurement. Instead a probe test that
throws was appended to `site/tests/bjorklund.test.mjs`, one of the six files
that previously ran nowhere in CI. The suite went to 278 tests with 1 failure,
naming the probe. Restored, `git diff --quiet` clean, back to 277 passing.

That is the direct evidence the step covers the previously-unrun files: the
script is `node --test tests/**/*.test.mjs`, a directory glob, so every file in
`site/tests` runs by construction and a new one is picked up with no wiring.
