## M006/S02 — task 2: guard the step, and close the slice

- `format` → exit 0
- `site-unit` → exit 0, 278 tests, 0 failures
- `doc-conformance` → exit 0, 257 tests, 0 failures
- `ledger` → exit 0, conforms with the slice `done`

The case went into `site/tests/doc-conformance-wiring.test.mjs`, whose stated
purpose is guarding this exact seam from vacuity. The runner names *which*
guardrail files run; this case guards the other half — that CI runs the whole
directory, so a file named in no runner still cannot go unrun.

It asserts on the command, not the step's `name`: a name is cosmetic and a
command is what executes.

Mutation proof: deleting the CI step failed the case with `no CI step runs
\`npm --prefix site test\`, so any site/tests file not named in
check-doc-conformance.sh runs nowhere in CI`. Restored, `git diff --quiet`
clean.

**The guard is itself protected.** `doc-conformance-wiring.test.mjs` is named in
`scripts/check-doc-conformance.sh`, so it runs in CI. This was checked rather
than assumed, because a guard that only runs on a developer's machine is the
precise failure this milestone exists to remove — and M005/S01's count guard is
exactly that, which is why its case was placed elsewhere.

#272 is discharged by this slice's pull request, which corrects its counts —
6 of 23 now, not the 7 of 21 it records — and closes it.

## M006/S02 — correction to the task 2 entry above

Two claims in the entry above are wrong. They are corrected here rather than
edited away, because this file is the record of what was run.

**"`doc-conformance` → 257 tests" was written without reading the output.** The
run printed 256 — unchanged — which is what exposed the second error.

**"The guard is itself protected … named in `scripts/check-doc-conformance.sh`"
was false.** `doc-conformance-wiring.test.mjs` appeared in that script only in a
*comment*; it was never in the `TESTS` array. The check that produced the claim
was `grep -c`, which counted the comment.

That made the guard circular: it was executed only by the CI step it guards, so
deleting the step would have removed the guard from CI along with it, and
nothing would have failed. The file is now in the `TESTS` array, so
`doc-conformance` runs it independently of the step.

**And the unprotected count was 7, not 6.** Measured against the `TESTS` array
rather than a grep over the whole file: 23 files on disk, 16 in the runner, 7
outside it — `bjorklund`, `doc-conformance-wiring`, `dump-mode`,
`preset-patterns`, `presets-json-schema`, `sample-loader`, `smf-writer`. #272's
figure of 7 was right; only its total of 21 had drifted. The ledger row is
corrected to match, and the pull request will correct the total rather than the
count.
