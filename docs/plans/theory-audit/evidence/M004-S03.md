**This weakens a rule deliberately.** S05 wrote `gam-structural-overlap` as *the
kotekan pair must share an onset; under `Kotekan L<n>` sangsih is the strict
complement, so they intersect nowhere by construction*. Seen before changing it:
`sangsih is L1, the strict complement of polos, so the pair intersect nowhere by
construction`.

Three things in the tree say that predicate was wrong:

- `theory-gamelan`'s own reference patch uses `L6` for its sangsih, so the rule
  condemned the worked example it was drawn from.
- Rule 4's parenthetical already discloses the limit: *"Poly's Kotekan `L1`
  implements the strict case; add deliberate doublings via a third lane or
  accent masks until kotekan modes ship."*
- Construction step 4 names the available remedy: *"accent masks on both pair
  lanes, or a sparse third lane striking with both at the gong point."*

The rule now checks step 4's remedy: a lane outside the pair sounds at the cycle
boundary together with a pair lane. Sangsih's own triple is deliberately not
used — under L-mode the engine derives its onsets from the source lane, so the
table does not describe what sounds. Polos is the pair member the table does
describe.

Chapter 5 passes without a marker: polos sounds on `{0,2,3,5,6}` and the Jegogan
bass on `{0,4}`, so a lane outside the pair already doubles the gong point. The
plan made that a prediction to check, with instructions to stop rather than
adjust the predicate until it passed.

Proved to bite: rotating the Jegogan to rotation 1 moves it to `{1,5}` and the
rule fails with `no lane outside the kotekan pair sounds on the cycle boundary`.
Restored by inverse edit.

A splice error while rewriting the rule dropped the object's closing brace and
the suite failed to parse — `SyntaxError: Unexpected token ']'`. Repaired before
anything was committed; noted because a green run after a parse error is not the
same evidence as a green run that never broke.
