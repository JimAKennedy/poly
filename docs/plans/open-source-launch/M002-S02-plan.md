## Task 1 — Both targets and the seeder build under a declared option, and each runs clean on its seeds

**Files:** modify `CMakeLists.txt`, `tests/CMakeLists.txt`; create
`tests/fuzz/fuzz_midi_reader.cpp`, `tests/fuzz/seed_corpus.cpp`.
**Produces:** targets `fuzz_state_io`, `fuzz_midi_reader`,
`fuzz_seed_corpus`; the corpus layout `<dir>/state_io/*.bin` and
`<dir>/midi_reader/*.mid`.

1. In `CMakeLists.txt`, directly after `option(ENABLE_COVERAGE …)`, add
   `option(BUILD_FUZZ_TESTS "Build the libFuzzer targets under tests/fuzz (needs Clang with -fsanitize=fuzzer)" OFF)`
   with a comment naming OS09: the option was referenced by
   `tests/CMakeLists.txt` and declared nowhere, so the fuzzer ran on no
   machine.
2. Configure with the option ON and Homebrew Clang, exactly the `fuzz` token's
   first command. It configures. Build `fuzz_state_io`: it builds — this is
   the first time the option has existed, so record it in the evidence.
3. Write `tests/fuzz/fuzz_midi_reader.cpp`, the same shape as
   `fuzz_state_io.cpp`: SPDX header, `LLVMFuzzerTestOneInput` calls
   `poly::parseSMF(data, size)` and then `poly::importMidiToLane(data, size,
   lane)` on a `poly::LaneConfig lane{}` whose `midiNote` is 36, and if the
   parse was valid also calls `poly::fitEuclidean(parsed.onsetsPpq,
   parsed.loopLengthPpq, parsed.tempoBpm)` directly. Return 0.
4. Write `tests/fuzz/seed_corpus.cpp`: `main(argc, argv)` takes one
   directory argument, creates `<dir>/state_io` and `<dir>/midi_reader` with
   `std::filesystem::create_directories`, and writes:
   - `state_io/groove-default.bin` — `writeGrooveState` of a default
     `GrooveState{}`;
   - `state_io/groove-preset-<i>.bin` for `i` in 0, 1, 2 — `writeGrooveState`
     of `GrooveState` after `applyPreset(i, …)` (use whatever
     `engine/include/poly/presets.h` names for loading factory preset `i`
     into a `GrooveState`; read the header before writing the call);
   - `state_io/scene-default.bin` — `writeSceneState` of a default
     `SceneState{}`;
   - `midi_reader/euclid-3-8.mid`, `euclid-5-12.mid`, `euclid-7-16.mid` —
     `writeSMF` over one cycle of E(k,n) at subdivision 16, built exactly as
     `euclideanEvents` in `tests/midi_reader_tests.cpp` builds them (copy
     that helper into the seeder; the seeder is a tool, not a test);
   - `midi_reader/two-instruments.mid` — `writeSMF` over the E(3,8) events at
     pitch 36 merged with the E(5,8) events at pitch 38;
   - `midi_reader/multitrack.mid` — `writeMultiTrackSMF` over the same merged
     events with a name callback returning `"kick"` for lane 0 and `"snare"`
     otherwise.
   Each write uses `std::ofstream` in binary mode; a write failure prints the
   path to stderr and returns 1. Print the count of files written and return 0.
5. In `tests/CMakeLists.txt`'s `if(BUILD_FUZZ_TESTS)` block add
   `fuzz_midi_reader` with the same five lines as `fuzz_state_io`, and
   `fuzz_seed_corpus` as a plain executable (link `poly_engine`,
   `cxx_std_20`, `jk_target_warnings`, no `-fsanitize=fuzzer`). Rewrite the
   block's header comment: three targets, what each is, that
   `fuzz_seed_corpus <dir>` writes the corpora, and that the nightly in
   `sanitizers.yml` runs them.
6. Run the `fuzz` token in full (60 seconds per target). Both fuzzers exit 0
   with no crash; record each target's final `#… DONE` line, corpus size, and
   the seeder's file count.
7. Run `engine-isolation`, `sanitizers`, `format`. Append evidence. Tick the
   box. Commit. No row closes yet: OS09 and OS10 both close on task 3's
   planted-bug proof.

## Task 2 — The nightly builds, seeds and runs them, and a crash files an issue

**Files:** modify `.github/workflows/sanitizers.yml`.
**Consumes:** the three targets and the corpus layout from task 1.

1. Add a job `fuzz` after `tsan-plugin` and before `notify`:
   - `name: libFuzzer (state_io, midi_reader)`, `runs-on: ubuntu-latest`,
     `timeout-minutes: 30`.
   - Checkout at the same pinned SHA as the other jobs; `sudo apt-get install
     -y ninja-build`.
   - Configure: `cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
     -DPOLY_ENGINE_ONLY=ON -DENABLE_ASAN=ON -DBUILD_FUZZ_TESTS=ON
     -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++`.
   - Build the three targets.
   - Seed: `./build/tests/fuzz_seed_corpus corpus`.
   - Two run steps, one per target, each
     `./build/tests/fuzz_<t> -max_total_time=300 -timeout=10 -rss_limit_mb=2048 -artifact_prefix=artifacts/<t>- corpus/<t>`
     after `mkdir -p artifacts`, with `LSAN_OPTIONS` pointing at
     `.github/lsan.supp` as the ASan job does.
   - `actions/upload-artifact` (same pinned SHA as `ci.yml` uses) with
     `if: failure()`, `name: fuzz-artifacts`, `path: artifacts/`,
     `if-no-files-found: ignore`.
   - A comment above the job naming OS09 and OS10 and stating the budget:
     300 seconds per target, bounded so the nightly finishes.
2. In `notify`: add `fuzz` to `needs`, and a line
   `[[ "${{ needs.fuzz.result }}" == "failure" ]] && FAILED="${FAILED} FUZZ"`
   after the `TSAN-PLUGIN` line. The issue title and label are unchanged, so
   a fuzz crash lands on the same open `sanitizer-failure` issue a sanitizer
   failure would.
3. The `permissions:` block task 1 of S01 added stays top-level; `fuzz`
   needs nothing beyond `contents: read`.
4. Run `node --test scripts/check-workflow-hygiene.mjs`,
   `jk-standards action-pinning`, `jk-standards workflow-permissions`: pass.
   Run `python3 -c "import yaml,sys; yaml.safe_load(open('.github/workflows/sanitizers.yml'))"`:
   the file parses.
5. Run `format`. Append evidence. Tick the box. Commit. No row closes yet.
