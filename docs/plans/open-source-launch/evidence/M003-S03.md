**Feasibility, checked first.** The VST3 SDK's AUv2 wrapper
(`public.sdk/source/vst/auwrapper/auwrapper.h`) subclasses
`MusicDeviceBase`; its `auresource.r` allows `kAudioUnitType_Effect` or
`kAudioUnitType_MusicDevice` and nothing else; `auwrapper.mm` implements
`kAudioUnitProperty_MIDIOutputCallback`, so the `aumu` can emit MIDI, but
Logic routes an instrument's MIDI to no other track — only a MIDI-FX `aumi`
unit's. The AUv3 wrapper likewise knows only the MusicDevice type. No
release workflow builds the AU. Supporting Logic therefore means a wrapper of
Poly's own.

**The decision.** Declined for the first release, by the owner on
2026-09-29, recorded in `M003-decisions.md`; M010/S02 (OS44) revisits it with
a wrapper spike. M007/S01 cites this decision when it is planned.

**Seen red first.** Both new tests failed on the unmodified tree: the guide
listed Logic Pro under Load Poly with AU loading steps and carried a Logic Pro
routing block, and neither file said Logic is not supported.

**What changed.** The README's DAW compatibility section and the guide's
Load Poly list say Logic Pro is not supported and why; the guide's Logic Pro
routing block is gone. The `build-au-macos` job comment and the AU target's
comment in `plugin/CMakeLists.txt` say the AU exists for validation only and
is shipped by no release, and point at the decisions file. The guide's "two
formats" and `Poly.component` install prose are untouched: OS41 (M004/S04)
rewrites them against this decision.
