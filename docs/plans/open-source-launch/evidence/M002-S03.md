## M002/S03 — after the first push: Ubuntu's GCC 13 fails the fatal engine on one line

- GCC 15.2 and Apple Clang fatal engine builds → 0 diagnostics after the fix
- `unit` → exit 0, 701 of 701
- `engine-isolation` → exit 0, 572 of 572
- `format` → exit 0
- 2026-09-24

**What CI found.** Six Linux jobs on PR #340 failed on the same line:
`rng.h:14:10: error: conversion to 'long long unsigned int' from 'uint64_t'
{aka 'long unsigned int'} may change the sign of the result
[-Werror=sign-conversion]`. On Linux `uint64_t` is `unsigned long` and a
`ULL` literal is `unsigned long long`; GCC 13 reports the mixed-rank multiply
as a sign conversion where the cast source is signed. GCC 15, Apple Clang and
Emscripten do not.

**The fix.** The four constants in `deterministicRand`'s mix are
`uint64_t{…}` rather than `ULL` literals, with the reason at the site. Same
values, same arithmetic; the golden tests are the proof.
