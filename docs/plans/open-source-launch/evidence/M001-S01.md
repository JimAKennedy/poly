### Two things the plan got wrong, corrected before they ran

**The SDK helper must be called from the top-level list file.** Called from
`plugin/CMakeLists.txt` it wrote `projectversion.h` into `build/plugin/` while
adding `build/` to the include path, and the first build failed with
`'projectversion.h' file not found`. `configure_file` resolves against the
*current* binary directory and the helper adds `PROJECT_BINARY_DIR`; the two
coincide only at the top level. The call now sits beside
`add_subdirectory(plugin)` with the reason in a comment.

**Three test targets compile plugin sources directly.** `poly_host_tests`,
`poly_probe_tests` and `poly_bridge_tests` include `plugin/source` rather than
linking `poly_plugin`, so the include directory the helper adds to the plugin
never reached them and the full build failed the same way. Each gains
`${PROJECT_BINARY_DIR}` beside `plugin/source`, with a comment.
