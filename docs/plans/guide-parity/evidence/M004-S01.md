## M004/S01 — task 1: a test that demands byte-identical renders, and the wiring that makes it pass

Observed failing first, as the plan requires. Before the dependency existed, all

The wiring landed in the same commit rather than a separate one. The plan

two tasks before either ran. The failure above is the record that matters.

- `npm --prefix site run build` → exit 0, 47 pages

**Determinism, as numbers rather than an adjective.** Two renders of one source,
each in its own child process: both 12648 bytes, identical SHA-256
(`f69b2bb532373676…`). Separate processes because "two builds" means two
processes; a same-process comparison cannot see state crossing that boundary.

No fixture is committed or compared. The emitted SVG carries browser-computed
geometry from font metrics (`viewBox="0 0 421.953125 70"`), so byte-identity
holds across builds on one machine and need not hold across machines — a
fixture would assert something false.

**`deterministicIds` is inert and is therefore absent.** Rendering with the flag
and without it produced identical bytes and an identical `id="mermaid-0"`:
`rehype-mermaid` gives each diagram a fresh page context, so the counter starts
at zero either way. Recorded in `src/lib/mermaid-config.mjs` so the next reader
does not re-add it believing it does something.

**The processor swap, measured.** `markdown.rehypePlugins` requires
`@astrojs/markdown-remark`, which replaces Astro 7's default Sätteri processor
for every page. Comparing a pre-change build against the post-change build:

| Comparison | Pages differing |
|---|---|
| raw bytes | 43 of 49 |
| ignoring inter-tag whitespace | 29 |
| ignoring entity style (`&amp;` vs `&#x26;`) | 19 |
| visible text only | **4** |
| visible text, after `dashes: 'oldschool'` | 1 |
| visible text, after the quote correction | 0 differing unintentionally |

The single remaining difference is the intended one: `(“&“s)` → `(“&”s)`.

**The dash lock bites.** Removing `smartypants: { dashes: 'oldschool' }` fails
`the markdown processor keeps \`--\` an en dash`; restoring it by an explicit
edit — not `git checkout`, since the tree carried uncommitted work — passes.
299 → 298 → 299.

**Carried in this commit and flagged:** `site/src/generated/counts.json` went
43 → 45 presets. The committed artifact was stale; the build regenerates it, so
the deployed site was never wrong. See `M004-decisions.md` for why it was folded
in rather than restored, and for the guard gap it exposes.

## M004/S01 — task 3: Chromium in the Pages deploy build job

- `format` → exit 0
- `site-unit` → exit 0, 302 tests, 0 failures
- `doc-conformance` → exit 0
- `doc-discipline` → exit 0
- `guards` → exit 0
- 2026-09-19

The plan said this task "cannot be proved locally beyond the guards". That was
wrong, and the task is better for it: the failure mode is *silence*, so a test
now ties the two facts together — if the Astro config renders Mermaid, every
workflow job that builds the site must install Playwright browsers. The rule is
derived from the config rather than hardcoding "deploy-site.yml needs chromium",
so backing the plugin out lifts the requirement instead of leaving a stale rule.

**Both arms proved, each reverted by an explicit edit:**

- Removing the install step from `deploy-site.yml`'s build job fails with
  `these jobs build the site with no Playwright browser installed, so
  rehype-mermaid will fail there: deploy-site.yml:build`. Restored, and `diff`
  confirmed the file identical to its backup.
- Breaking the job-matcher so it selects nothing fails with `found no workflow
  job that builds the site; this test has stopped checking anything` — the
  vacuity guard, which is what stops a workflow rename turning this into a green
  test over an empty set.

Job coverage, read from the parsed YAML rather than by eye: `build`
builds=True installs-chromium=True; `deploy` builds=False; `verify-deployed`
builds=False installs-chromium=True (pre-existing, untouched).

**`js-yaml` is now a declared devDependency**, pinned `^4.3.2`. The new test
uses it, and it was resolving only transitively — as `prose-pattern-claims.test.mjs`
already did. Declaring it at `latest` first installed **v5, which drops the
default export** and broke that existing test (302 → 299, 1 failure). Pinned to
the 4.x already in the lockfile instead, which was the actual intent: make the
dependency explicit, not upgrade it. Recorded because a future Dependabot bump
to v5 will now surface as a visible CI failure rather than a silent one.

`scripts/check-release-workflow.mjs` targets `release.yml` only — zero
references to `deploy-site` — so no locked workflow contract is affected.
