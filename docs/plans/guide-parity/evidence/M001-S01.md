## M001/S01 — task 1: the mode field and the tempo curve

- `format` → exit 0
- `unit` → exit 0, 630 tests, 0 failures
- `engine-isolation` → exit 0, 507 tests, 0 failures

Written test-first; the four cases failed to compile because `swingRatioAt` did
not exist.

What they pin, chosen so a wrong curve cannot satisfy them:

| Case | Guards |
|---|---|
| reaches beyond triplet at ballad tempo | the ceiling the fixed `/3` divisor imposes |
| narrows **monotonically** across six sampled tempi | the property, not a pair of points — a curve that wiggles satisfies two samples and is still wrong |
| approaches straight near 300 BPM | the far end of the shape, and that it never inverts |
| zero amount is straight at every tempo | that the parameter still means what it meant |

**The coefficients are stated as ours.** The comment says the curve reproduces
the *shape* Friberg & Sundström (2002) report and that the values are Poly's,
so refining them against a source in hand is a data change needing no code.
That is the framing M003 used for the jembe profile, and claiming these were
measured values would be the citation failure the theory-audit programme
existed to remove.

`swingOffsetFraction` is separate from the ratio deliberately: the ratio is the
musical claim and the displacement is its consequence, and at a 2:1 ratio the
fraction agrees with what the fixed mapping already produces — the two paths
meet where they should.

**The size guard fired and was answered with a measurement.** `GrooveState`
grows 17936 → 18000, **+64 bytes**, the smallest growth the guard has recorded:
a `uint8_t` per lane costing 8 bytes each with alignment. The three-copy
pipeline runs at **0.70 µs/block, 0.02% of a 128-sample block period**.

## M001/S01 — task 2: swing reads the curve, and the lookahead follows

- `format` → exit 0
- `unit` → exit 0, 635 tests, 0 failures
- `engine-isolation` → exit 0, 512 tests, 0 failures
- `rt-safety` → exit 0

**A failure that was mine, not the engine's.** `FixedLaneMatchesThePreM001Mapping`
failed at 4e-9 because the expectation used double `0.6` where `swingAmount` is
`float`. The engine was right; the expectation is now computed from
`static_cast<double>(0.6f)`. M003/S01 hit the same thing in this same file.

**Two mutation rounds, and they found different things.**

| Probe | Result |
|---|---|
| swing ignores the mode, always Fixed | `AdaptiveLaneSwingsDifferentlyAtDifferentTempi` **fails**; the Fixed cases and the pure-curve cases correctly still pass |
| the lookahead bound left at the fixed `/3` figure | `SplitRenderingMatchesWholeRenderingWhenAdaptive` **fails** |

The second is the one worth reporting. **M003/S03's equivalent split test passed
both before and after its bound fix** — the additive path enumerates whole cycles
with a margin that swamped the shortfall, so that fix was defensive rather than
proven. Here the shortfall is large enough to drop an onset at a seam, and the
test catches it. The bound is proven, not assumed, and the difference between
the two cases is recorded so nobody reads across from one to the other.

**The byte-identity golden.** All 45 factory presets render identically with the
mode off, and the test additionally asserts no preset ships `TempoAdaptive` —
so the claim is "presets are unmoved", not "presets happen to be unmoved today".
A preset adopting the mode later fails this until the golden is reconsidered,
which is the intended friction.

`FixedLaneIsUnchangedByTempo` exists as the control for the adaptive case:
without it, "slow swings wider than fast" could pass for a reason unrelated to
the curve.

## M001/S01 — task 3: `12-jazz` stops prescribing a per-tempo value

- `format` → exit 0
- `site-unit` → exit 0, 288 tests, 0 failures
- `doc-conformance` → exit 0
- `doc-discipline` → exit 0

Written test-first: `M001-S01-adaptive-swing` failed against the unedited page,
and failed again when the instruction was restored after the rewrite — restored
**by explicit edit rather than `git checkout`**, which in M007/S03 discarded
uncommitted work.

The page said "Set the ride cymbal's swing to 0.4-0.5 for a medium-tempo feel"
three paragraphs after teaching that swing "varies continuously with tempo". The
instruction was the workaround and is gone.

**What deliberately stayed.** *Per-lane independence* — the ride and hi-hat
swinging at different ratios — is not the workaround. It is a separate claim the
mode does not address, and the claim's `present` list requires it to survive, so
a later edit cannot quietly drop it while satisfying the rest.

`docs/engine-spec.md` gains a Swing section: `doc-drift` requires it for any
change to `types.h`, and the section records the thing a reader would otherwise
have to derive — that the parameter keeps its 0–1 range and only the meaning of
`1.0` moves.
