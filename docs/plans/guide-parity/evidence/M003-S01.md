## M003/S01 — task 1: the sequence field, and the pitch it supplies

- `format` → exit 0
- `unit` → exit 0, 686 tests, 0 failures
- `engine-isolation` → exit 0, 563 tests, 0 failures
- `rt-safety` → exit 0

Written test-first; the five helper cases failed to compile because neither the
fields nor `noteSequencePitch` existed.

**The naming, which the slice's definition of done requires be recorded.**
`noteSequence` / `noteSequenceLength`. `phraseLength`, `phraseGap` and
`phraseOffset` already exist and mean *gating* rather than content — #245 flags
the collision explicitly — so nothing here borrows the word.

**Indexed by absolute step position, not hit ordinal.** A five-note sequence
over a seven-step cycle phases, which is the device #245 asks for, and a case
asserts it directly. The hit-ordinal reading is closer to the issue's wording
but would make the melody a function of the mutation rolls: one dropped hit
re-voices everything after it.

**Per-note durations are gate length only,** and the case that guards it asserts
the *onsets are unchanged* while the gate length differs. That is the decision
keeping pitch orthogonal to placement: durations advancing the clock would be a
second mechanism for placing onsets beside `subdivisionProfile` and `cellSizes`,
which engine-capability M003 spent a slice resolving.

**The render cases were written before the wiring,** per this milestone's
standing instruction, and two of them failed immediately — which is the point.
M002/S02's probe killed nothing because every case tested the helper directly.

| Probe | Result |
|---|---|
| pitch ignores the sequence | `EmittedPitchesFollowTheSequence` **fails** |
| per-note duration ignored | `PerNoteDurationsChangeLengthButNotOnsets` **fails**, `0.125 vs 0.125` |

**A false green from my own probe harness, caught.** The second probe first
reported *passing* when run through a shell helper that applied the edit,
`touch`ed, rebuilt and ran `ctest` in quick succession — back-to-back touches
inside one second defeat make's timestamp comparison, so `ctest` ran the
previous binary. Applying the same probe directly and inspecting the failure
gave the truth. This is the fourth stale-build incident of the programme and
the first inside the tooling built to avoid it; the plans' standing instruction
to rebuild and check now needs to extend to *waiting* for the clock.

**The size guard fired and was answered with a measurement.** `GrooveState`
grows 18192 → 18768, **+576 bytes** — 72 per lane for eight entries and a
length. Bounded at eight deliberately, per #245's own proposal: `kMaxSteps`
entries would have been about 4 KB for a field most lanes never set. The
three-copy pipeline measures **0.68 µs/block, 0.02% of a 128-sample block
period**.
