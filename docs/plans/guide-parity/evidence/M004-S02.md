### The guard bites on all four arms

Each mutation reverted by an **explicit edit**, never `git checkout`, and
`git diff --quiet` confirmed identical restoration each time.

| Arm | Mutation | Result |
|---|---|---|
| detects ASCII | appended `┌── reintroduced ascii` to `ARCHITECTURE.md` | `guards` exit 1, `ARCHITECTURE.md:36` named |
| hatch honoured | — | 3 files exempted, each listed with its reason |
| empty reason fails | emptied the audit file's reason | `guards` exit 1, "marker carries no reason" |
| cannot go vacuous | broke the `doc_roots` config parse | `guards` exit 1, "refusing to report a pass" |

The first attempt at arm 1 was a **no-op** — the replacement anchor did not
exist in the file, so nothing changed and the guard passed. `git diff` was clean,
which is what exposed it. Recorded because a mutation proof that does not mutate
reads exactly like a guard that does not work.

### Row GP11's test bites on both arms

- Breaking `ARCHITECTURE.md`'s fence → fails naming the file and mermaid's own
  lexical error. Restored identically.
- Making the collector match a fence type that does not exist → trips the
  non-vacuity guard, rather than passing over an empty set.

### Facts established by measurement, not assumption

- **Invalid Mermaid fails `astro build` with exit 1** and emits no page. An
  earlier commit message in this slice claimed it renders an error graphic; that
  was wrong. The website was never at risk, because `site-e2e` and the Pages
  deploy both build the site.
- **Build cost is negligible:** 47 pages in 1.91s with all five diagrams against
  1.66–1.79s before. The browser starts once, so five diagrams cost about what
  one did.
- **`check-guards.sh` printed a hardcoded count.** It said "13 guard
  invocation(s)" — correct until this slice made it 14. Now computed from the
  invocations, proved by adding a probe guard and watching it read 15, then 14.

### Two limits stated rather than papered over

- The fence test renders against the pinned mermaid. GitHub renders with its
  own, and the versions can diverge; no local check closes that.
- The Pages deploy now depends on a browser launching, so a Chromium failure in
  CI blocks a docs deploy rather than merely failing a test.

### Left undone, deliberately

The two UI wireframes can drift from the UI they depict, and they predate the
webui migration. That is a real problem and the exemption does not solve it —
but neither would Mermaid. Replacing them with screenshots needs a capture
pipeline, alt text and `check-site-assets` wiring, which is its own slice.
