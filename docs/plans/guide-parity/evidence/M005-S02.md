## M005/S02 — task 1: re-encode assertion 3 so it survives the round trip

Watched failing first, and the failure is the nightly's, character for
character. `HostTests.NoteMapEncoding_SurvivesStateRoundTrip` was added before
the fix and reported:

```
noteMap[1] did not survive the state round trip: got 127, expected 126.
```

The 2026-09-16 nightly (run `35051069155`) reported
`torn-read: final noteMap[1]=127 but map[0] implies 126`. The same numbers, from
a test with **no threading in it at all**.

- `format` → exit 0
- `unit` → exit 0, 692 tests, 0 failures (up from 691: the round-trip test)
- 2026-09-19

**The change.** `encodeNoteMapField` masks with `0x7F` instead of `0x7FFF`, and
the three comparison masks in assertion 3 follow. Because `i < 128`, XOR keeps
every value inside the same 7-bit block, so nothing reaches
`sanitizeSceneState`'s `[0,127]` clamp and `map[i] == map[0] ^ i` holds exactly.

**Measured, not assumed.** Across writeIds 1–100000, the old encoding broke the
invariant for **99,608** of them; the new one breaks it for **0**.

**`sanitizeSceneState` was deliberately not touched.** The clamp defends against
a host supplying corrupt state, and `tests/state_migration_tests.cpp` asserts
that behaviour. Changing the product to satisfy a test would invert which of the
two is authoritative.

The comment above the encoding now says why the mask is 7 bits rather than 15.
Without that sentence the next person widens it again and re-opens #142.
