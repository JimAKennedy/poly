## M005/S02 — task 1: re-encode assertion 3 so it survives the round trip

Watched failing first, and the failure is the nightly's, character for
character. `HostTests.NoteMapEncoding_SurvivesStateRoundTrip` was added before
the fix and reported:

```
noteMap[1] did not survive the state round trip: got 127, expected 126.
```

The 2026-09-16 nightly (run `35051069155`) reported
`torn-read: final noteMap[1]=127 but map[0] implies 126`. The same numbers, from
a test with **no threading in it at all**.

- `format` → exit 0
- `unit` → exit 0, 692 tests, 0 failures (up from 691: the round-trip test)
- 2026-09-19

**The change.** `encodeNoteMapField` masks with `0x7F` instead of `0x7FFF`, and
the three comparison masks in assertion 3 follow. Because `i < 128`, XOR keeps
every value inside the same 7-bit block, so nothing reaches
`sanitizeSceneState`'s `[0,127]` clamp and `map[i] == map[0] ^ i` holds exactly.

**Measured, not assumed.** Across writeIds 1–100000, the old encoding broke the
invariant for **99,608** of them; the new one breaks it for **0**.

**`sanitizeSceneState` was deliberately not touched.** The clamp defends against
a host supplying corrupt state, and `tests/state_migration_tests.cpp` asserts
that behaviour. Changing the product to satisfy a test would invert which of the
two is authoritative.

The comment above the encoding now says why the mask is 7 bits rather than 15.
Without that sentence the next person widens it again and re-opens #142.

## M005/S02 — task 2: the narrowed check still detects a genuine tear

Narrowing the encoding makes an assertion stop firing, so the burden is to show
it still fires on what it exists for. `HostTests.NoteMapInvariant_StillDetectsATear`
builds a map whose first 64 entries come from writeId 100000 and whose last 64
come from 100001 — what a mid-flight publish would leave behind — and asserts
the reconstruct refuses it. It also asserts a clean single-writeId map is
accepted, so the check cannot be broken in the other direction.

- `format` → exit 0
- `unit` → exit 0, **693** tests, 0 failures (691 before this slice)
- `rt-safety` → exit 0
- `sanitizers` → exit 0, all five variants: ASan 568, UBSan 568, TSan 568,
  ASan-plugin 57 + 59 bridge, TSan-plugin 57
- 2026-09-19

**Both arms mutation-proved, each reverted by explicit edit:**

| Arm | Mutation | Result |
|---|---|---|
| the tear check is not vacuous | make the reconstruct always return true | fails — *"a map torn between writeId 100000 and 100001 was accepted; the 7-bit encoding has made the torn-read check vacuous"* |
| the encoding cannot be widened back | restore the `0x7FFF` mask | fails — *"noteMap[1] did not survive the state round trip: got 127, expected 126"* |

**The second arm reported a false pass on its first attempt**, and is recorded
because it nearly stood. The mutation was applied and the binary rebuilt within
the same second, so `make`'s timestamp comparison did not fire and `ctest` ran
the previous binary — the widened encoding appeared to pass. Re-run with the
mutation verified in the file by `grep` and a full second before building, it
failed as it should. This is the same trap that produced a false green earlier
in this programme, in M003; a mutation proof that does not rebuild is
indistinguishable from a guard that does not work.

### #142 and #274 are one defect with two observers, and both are answered

Per the decision recorded at planning, no row was added for #274. The triage
attributes every occurrence:

Both issues can close: #142 because every one of its 23 occurrences is now

same cause as Group B.

### What this slice did not do

**No product code changed.** `plugin/source/` is untouched, and so is
`sanitizeSceneState`. The milestone set out to fix a memory or threading defect
in plugin code and found that there was not one to fix: the real race had
already been fixed in August, and what remained was a test asserting a property
the serialization layer never promised.

That is a smaller result than GP12 anticipated and a more useful one than
suppressing a flake would have been. The nightly stops refiling #142, and it
stops because the assertion is now sound rather than because it was silenced.
