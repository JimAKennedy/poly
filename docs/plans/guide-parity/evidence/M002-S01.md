**A test that asserted the wrong unit's responsibility.**
`RefusesAnUnusableReference` originally expected `computeStepWeights` to refuse
an out-of-range lane index. It cannot: it receives an **already-resolved**
pattern, so the only bad references it can see are a negative index and a
self-reference. Whether lane N exists, and whether it points back, is the
resolver's question — which is what `referenceLaneUsable` exists for. The test
is now split along that line, and the split is the honest one rather than a
loosened assertion.

| Case | Guards |
|---|---|
| neutral with no reference lane | the byte-identity guarantee, as arithmetic rather than a promise |
| positive strength attracts adds | the mechanism does something |
| **negative strength inverts it** | that the *sign* is read — without this, an implementation reading only the magnitude would pass |
| drop moves opposite to add | protecting what attraction favours, the row's stated behaviour |
| refuses what it can see | self-reference and negative index |
| `referenceLaneUsable` refuses out-of-range, self and mutual | the resolver's half, mirroring kotekan's guard |
| refuses a step outside the cycle | that a bad index is not read out of bounds |

**The design's size claim, measured.** `GrooveState` grows 18000 → 18064,
**+64 bytes** — 8 per lane for an `int` and a `float`. The alternative the
issues proposed, four 64-float arrays per lane, would have been roughly 8 KB on
a struct copied three times per block. The three-copy pipeline measures
**0.46 µs/block, 0.02% of a 128-sample block period**.
