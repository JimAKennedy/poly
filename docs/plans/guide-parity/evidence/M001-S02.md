## M001/S02 — task 1: a correlated noise source, proved correlated

- `format` → exit 0
- `unit` → exit 0, 639 tests, 0 failures
- `engine-isolation` → exit 0, 516 tests, 0 failures

Written test-first; the four cases failed to compile because `correlatedNoise`
did not exist.

`correlatedNoise` sums four octaves of value noise over the absolute step index:
each octave interpolates between hashed lattice points with a smoothstep, and
the long-period octaves carry most of the amplitude, which is what produces
drift rather than jitter. Weights sum to 1.0 so the result stays in [-1, 1] by
construction rather than by a clamp that would hide a bug.

**The correlation case is the only one that discriminates, and that was proved
rather than assumed.** Pointing the helper back at `deterministicRand`:

| Case | Under white noise |
|---|---|
| adjacent samples closer than distant ones | **fails** |
| stays within unit range | passes |
| pure function of the step index | passes |
| lanes on one seed do not move together | passes |

The three that survive are not redundant — they pin properties the replacement
could plausibly have broken — but they are true of white noise too, so the first
case is the one carrying the slice's claim. Naming which case does the work
matters here: this programme has repeatedly found predicates that read like
proofs and cannot fail.

Determinism is a requirement rather than a nicety: #151 states it, and the value
depends only on `(seed, laneId, absStep)`, so a locate or a loop reproduces it
and no state accumulates between `renderRange` calls.

## M001/S02 — task 3: two pages stop calling it random

- `format` → exit 0
- `site-unit` → exit 0, 290 tests, 0 failures
- `doc-conformance` → exit 0

Neither page was wrong, which shaped how the claims are written. They assert the
correction is **present** rather than that a falsehood is **absent**, and each
claim's `rule` says so — a reviewer reading a forbidden-less claim would
otherwise wonder what was being corrected.

`appendix-design-decisions.mdx` listed "humanize jitter" among the engine's
deterministic randomness sources. Still true of the default; it now names both
shapes, because a record naming only white noise understates what the engine
does. `18-editors-and-views.mdx` contrasted micro-timing with "Humanize, which
adds a different random displacement on every cycle" — a correct and useful
contrast that now says which mode it means, so it survives the feature rather
than being quietly outgrown by it.

**The first mutation attempt was the wrong shape, and that is worth recording.**
A `present`-only claim cannot be broken by *adding* text, so re-inserting the old
phrasing alongside the new one failed nothing. The regression that matters is the
correction being removed, and probing that fails both claims by name. A
mutation round that proves nothing is exactly as misleading as no mutation round.
