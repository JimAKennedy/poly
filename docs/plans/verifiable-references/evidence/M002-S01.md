## M002/S01 — task 3: the archive root comes from the environment

- `format` → exit 0
- `site-unit` → exit 0, 321 tests, 321 pass, 0 fail
- `guards` → exit 0
- 2026-09-20

The four cases were seen red before the module existed
(`ERR_MODULE_NOT_FOUND: …/site/src/data/references-archive.mjs`).

The rule that matters is proved in **two independent places**, which is the
point of step 5: a manifest record was given an absolute path under a home
directory, and

- `site-unit` → red, the bare-filename case naming the offending entry
- `guards` → **exit 1**, `check-personal-paths` naming the file

A guard only the test catches leaves the committed-path failure mode open, since
the test is not what runs on a contributor's first push. Both arms fire, and the
tree was restored byte-identical afterwards.

`resolveArchiveFile` rejects rather than normalises: `../etc/passwd`,
`sub/dir.pdf`, `..`, `''` and `a\b.pdf` all throw. Silently cleaning a traversal
up would make the manifest's contract "a path we will try to make safe" instead
of "a name", and the whole reason the field is a bare filename is that a path in
a tracked file is how a machine-specific root gets committed.

A whitespace-only `POLY_REFERENCES_ARCHIVE` falls back to `.references/` rather
than resolving to an empty root: an exported-but-empty variable is a
configuration mistake, not a request to treat the filesystem root as the archive.
