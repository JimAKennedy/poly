with the `.show` rule deleted. The `role="group"` and `aria-label` were already
correct and were not touched.

## M001/S01 — task 2: the bars chip carries per-bar progress while capturing

- `format` → exit 0
- `webui-e2e` → exit 0, 386 passed
- 2026-09-21

Seen red before the change: `toHaveText` expected `3/8 bars`, the chip rendered
`8 bars` regardless of capture state.

`updateCaptureChips()` now renders `${floor(capProg)+1}/${bars} bars` while
`capState === 2` and the plain count otherwise. Progress is read from
`lastFrame.capProg`, never from a local counter — the comment above that
function records that the chips track host truth, and a second source of
progress would be the defect it exists to prevent.

Proved in two directions rather than one:

- making the label unconditional again → **red**, and **no other spec broke**,
  so the case is specific to the behaviour it names
- the `1-32 stepper` case still passes → the idle label is unchanged, so this is
  additive rather than a replacement

The numerator matches what the capline used, `Math.min(bars, floor(prog) + 1)`,
so the readout that leaves with Cloth in M001/S02 says the same thing in its new
home.
