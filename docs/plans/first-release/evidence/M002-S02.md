**This is the one task in the milestone planned to end red.** The pages move
here; the tests that read them are repointed in task 2. The plan declared it in
advance so the commit records a known red rather than discovering one — M001
shipped two commits against unread gate results, which is what that declaration
is for.

Twelve files moved with `git mv`, so the history follows them. `git status`
shows 12 renames and nothing else.

**The imports are untouched and still resolve.** Every moved page still reads
`import PolyPatch from '../../components/PolyPatch.astro'`, which normalises
from the new directory to `site/src/components/PolyPatch.astro` — the same file
as before. That is the whole reason the destination is a sibling under
`site/src/content/` rather than `docs/theory/`.

**The build emits no theory route**, checked by inspecting the output rather
than by the absence of an error: `npm --prefix site run build` exits 0 and
reports 35 pages; `find site/dist -path '*theory-*' -name '*.html'` returns
**0** against 37 HTML files total. A collection that had silently picked the new
directory up would have built them without complaining.

`literature-enrichment`, `scope-framing`, `theory-audit-claims`,
`theory-euclidean-guardrail` and `theory-patch-conformance`.

One failure is **not** ENOENT and is worth naming separately:
`M006/S02: every appendix entry is cited by a page, or says it is unread`. That

and with the deep dives outside that root the 66 entries only they cite now look
orphaned. It is the same class of problem — a guard reading the old location —
and task 2 repoints it. It is **not** a reason to trim the shipping appendix
here: that is M003's FR19, and doing it in this slice would be a scope breach
hiding inside a path move.
