### The census was the suite, not a grep

The plan said ten test files. **Six** needed changing, and they were not the six
a grep would have named — the suite named them by failing.

Five failed with `ENOENT` and share one cause: `const DOCS = join(HERE, '..',
'src', 'content', 'docs')`. Four of those five read shipping chapters **and**
deep dives in the same test, so a blanket repoint of `DOCS` would have broken
them. Each gained a `docRoot(file)` resolver instead — `theory-*` to the new
root, everything else to `docs` — which leaves every call site unchanged.

Three more failures had three different causes, and none was an `ENOENT`:

| Guard | Why it failed | Fix |
|---|---|---|
| `M006/S02: every appendix entry is cited by a page` | `readdir(DOCS)` never enumerated the moved pages, so the 66 entries only they cite looked orphaned | enumerate **both** roots |
| `S01-F24: the About page … reachable from every theory page` | same `readdir`, so it found 0 theory pages where it requires 12 | read the theory root |
| `S02-F18-theory`, `S04-F20-theory` in `citation-tier` | its own `loadSource` was rooted at `DOCS` | `docRoot` there too |

`citation-tier` was in none of the five ENOENT files. Its claim helper reports a
missing file as a failed claim rather than an `ENOENT`, so a grep for `ENOENT`
would have missed it and a grep for `theory-` would have found it without
saying it mattered.

### No assertion changed

The diff across the six files is `join(DOCS, x)` becoming
`join(docRoot(x), x)`, two `readdir` calls gaining a root, and comments. The
plan's rule for this task was that an assertion changing here is a scope breach
hiding inside a refactor; the diff was read line by line against that rule.

### The plan's mutation was impossible, and a better one exists

Step 3 said to prove the mapping still bites by *"touching one of the sources
the drift map pairs with a theory doc"*. There are none. All twelve theory
entries carry a `doc:` and a `reason:` and **no `sources:` key** — they are
completeness *declarations* ("no repo source surface"), not source-to-doc
mappings. Nothing can be touched to make `doc-drift` fire for them, and the
first run confirmed it: `doc-drift: no mapped sources touched`.

The step's intent — prove these entries still do something — is satisfiable by a
mutation it did not name. Pointing one entry at a file that does not exist fails
`doc-completeness`:

```
exit 1
::error file=site/src/content/theory/theory-DOES-NOT-EXIST.mdx,line=1::
  Doc completeness: cannot_drift entry …
```

So the entries are **not** inert after the move, which was the real question:
`doc-completeness` validates that every declared path resolves, and the repoint
is what keeps twelve of them resolving. Reverted after proving.

## M002/S02 — task 4: the deep dives carry their own bibliography

- `format` → exit 0
- `site-unit` → exit 0, **326 pass, 0 fail**
- `doc-conformance` → exit 0
- 2026-09-21

`site/src/content/theory/theory-references.mdx` holds **93 entries** — every
anchor any deep dive cites, 66 exclusively theirs and 27 shared with shipping
pages.

**Derived, not curated.** The set was read out of the moved pages and filtered
from the shipping appendix programmatically, so it cannot disagree with what the
pages actually cite. Sections that ended up with no surviving entry were dropped
rather than left as empty headings. A hand-picked list is exactly where a missed
anchor hides, and a missed anchor here is a citation that dangles the day the
pages are published again — silently, because `research_provenance`'s roots stop
at `site/src/content/docs` and no longer scan them.

**Both arms of the guard are proved:**

| mutation | result |
|---|---|
| an entry is deleted from `theory-references.mdx` | **red** — *cited by a deep dive but not defined* |
| an entry nothing cites is added | **red** — *defined but cited by no deep dive* |

The second arm matters as much as the first: the bundle is meant to carry what
it needs, not a copy of the shipping appendix. Without it, the honest way to
pass would be to copy all 107 entries.

The guard also throws rather than passing vacuously if the deep dives move
again — an empty page set is an error, not a green run.

### One consequence, fixed in the same task

`theory-references.mdx` is a thirteenth `theory-*.mdx` file, which broke
`S01-F24`'s assertion that there are exactly twelve deep dives — a guard this
slice had repointed one task earlier. It is a bibliography, not a deep dive, and
carries no About link, so it is excluded from that count the same way this
task's own guard excludes it.
