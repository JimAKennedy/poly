## M002/S02 — task 2: the test files follow them

**324 before the move, 324 after.** That equality is the check the plan asked

### The census was the suite, not a grep

The plan said ten test files. **Six** needed changing, and they were not the six
a grep would have named — the suite named them by failing.

Five failed with `ENOENT` and share one cause: `const DOCS = join(HERE, '..',
'src', 'content', 'docs')`. Four of those five read shipping chapters **and**
deep dives in the same test, so a blanket repoint of `DOCS` would have broken
them. Each gained a `docRoot(file)` resolver instead — `theory-*` to the new
root, everything else to `docs` — which leaves every call site unchanged.

Three more failures had three different causes, and none was an `ENOENT`:

| Guard | Why it failed | Fix |
|---|---|---|
| `M006/S02: every appendix entry is cited by a page` | `readdir(DOCS)` never enumerated the moved pages, so the 66 entries only they cite looked orphaned | enumerate **both** roots |
| `S01-F24: the About page … reachable from every theory page` | same `readdir`, so it found 0 theory pages where it requires 12 | read the theory root |
| `S02-F18-theory`, `S04-F20-theory` in `citation-tier` | its own `loadSource` was rooted at `DOCS` | `docRoot` there too |

`citation-tier` was in none of the five ENOENT files. Its claim helper reports a
missing file as a failed claim rather than an `ENOENT`, so a grep for `ENOENT`
would have missed it and a grep for `theory-` would have found it without
saying it mattered.

### No assertion changed

The diff across the six files is `join(DOCS, x)` becoming
`join(docRoot(x), x)`, two `readdir` calls gaining a root, and comments. The
plan's rule for this task was that an assertion changing here is a scope breach
hiding inside a refactor; the diff was read line by line against that rule.
